# Ledger Implant Detector

> **⚠️ STATUS: CONCEPT — NOT YET VALIDATED (rev 0.1)**
>
> This hardware has **not been built or tested yet**. The schematic, layout and
> detection method are a first-pass concept. Expect errata. Do not rely on this
> device to declare a wallet "clean" until the design has been fabricated,
> characterised against known-good and known-tampered devices, and this banner
> has been removed.

A small hand-held tool for spotting **extra conductive structures hidden inside
the plastic shell of a hardware wallet** (e.g. a Ledger). The target threat is
a supply-chain implant that adds a cellular (LTE) modem to the device: such
implants need a comparatively large antenna, i.e. a sizeable area of copper
that is not present in a genuine unit.

## Detection approach

The project contains two complementary pieces of hardware:

### 1. Capacitive array detector (`hardware/detector`) — primary tool

An 8-electrode capacitive sensing head driven by two TI **FDC2214** 28-bit
capacitance-to-digital converters (LC-resonant, EMI-tolerant). Each electrode
is a 15 × 15 mm copper plate on the bottom of the board; any conductor near a
plate (an antenna trace, a ground plane, a battery…) increases that plate's
capacitance and lowers its resonance frequency.

The detector does **not** identify an antenna by itself — a genuine wallet
also contains copper (PCB, battery, display, NFC coil on newer models). The
method is **differential**:

1. Lay a *known-genuine* unit of the same model on the head in a fixed
   orientation (a 3D-printed jig is recommended) and record the 8-channel
   signature (the "reference").
2. Lay the unit under test in the same position and compare.
3. A significant positive deviation localised to one or more electrodes means
   "more conductor here than in the reference" → open the device / investigate.

The head is 66 × 32 mm, which covers a Nano S Plus / Nano X in a single pass;
Stax / Flex need two or more positions.

Firmware streams raw readings over USB (CDC serial) for a host-side tool, and
can also give standalone feedback via two LEDs and a piezo buzzer
(metal-detector style pitch). A Qwiic/STEMMA-QT connector allows an optional
I²C OLED.

### 2. Near-field RF loop probe (`hardware/rf_probe`) — secondary tool

A passive PCB H-field loop probe with an edge SMA connector, meant to be used
with an inexpensive VNA (NanoVNA / LiteVNA, 600 MHz – 3 GHz sweep). Sweeping
S11 while hovering over the device lets you look for **resonances in the LTE
bands** that a genuine unit should not exhibit. This is complementary to the
capacitive method: capacitance tells you *where there is extra copper*, the RF
sweep hints at *whether that copper is tuned like an antenna*. Results are
again comparative (reference unit vs. unit under test); the device's own
ground plane, battery, Bluetooth antenna (Nano X / Stax / Flex) and NFC coil
all produce responses of their own.

## Repository layout

```
hardware/
  lib/                 project symbol + footprint library (FDC2214, electrode, loop probe)
  detector/            KiCad 10 project: capacitive array detector (4-layer)
    fab/               gerbers, drill, BOM, pick-and-place (generated)
  rf_probe/            KiCad 10 project: near-field loop probe (2-layer)
    fab/
tools/                 Python generators used to produce the KiCad files
```

The KiCad files are generated by the scripts in `tools/` (so the design is
reviewable as code), but they are normal KiCad projects: once you start editing
them by hand in KiCad, treat the KiCad files as the source of truth.

## Detector board summary

| Block | Part | Notes |
|---|---|---|
| CDC ×2 | TI FDC2214RGHR | I²C 0x2A (U1) / 0x2B (U2), single-ended sensors |
| Tank ×8 | 18 µH (Bourns CMH322522-180KL) ‖ 33 pF C0G 1 % | ≈ 5–6.5 MHz, values from TI datasheet/EVM |
| Clock | 40 MHz CMOS oscillator (Abracon ASE) | shared by both FDCs |
| MCU | STM32F042F6P6 (TSSOP-20) | crystal-less USB FS, ROM USB-DFU bootloader |
| USB | USB-C (HRO TYPE-C-31-M-12), USBLC6-2SC6 ESD | 5.1 kΩ CC pull-downs (sink) |
| Power | AP2112K-3.3 LDO | |
| UI | green + red LED, Murata PKLCS1212E piezo, button | |
| Expansion | JST-SH 4-pin (Qwiic pinout), 5-pin SWD header | |

Stack-up: 4 layers, 1.6 mm. F.Cu = components/routing, In1 = solid GND
(acts as passive shield behind the electrodes so the hand holding the tool is
not sensed), In2 = routing/3V3 *only outside the electrode areas*, B.Cu =
electrodes (covered by solder mask).

        ├──────┼──────┼──────┼──────┤│                             │

|---|---|---|
| E1 / E2 / E5 / E6 | U1 (0x2A) | CH0 / CH1 / CH2 / CH3 |

### MCU pin map

| Pin | Function |
|---|---|
| PF0 / PF1 | I2C1 SDA / SCL (FDCs + Qwiic) |
| PA0 / PA1 | FDC U1 / U2 INTB (open-drain, 10 k pull-up) |
| PA2 | FDC SD (shutdown, both chips, 100 k pull-down = running) |
| PA3 / PA4 | LED green / red (active high) |
| PA5 | button SW1 (to GND, use internal pull-up) |
| PA6 | piezo buzzer (TIM3_CH1 / TIM16_CH1) |
| PA11 / PA12 | USB D− / D+ (pins 17/18, needs SYSCFG pin remap) |
| PA13 / PA14 | SWDIO / SWCLK |
| BOOT0 | SW2 to 3V3 — hold while plugging USB to enter ROM DFU |

### Suggested FDC2214 configuration (starting point, from datasheet §8.2.3)

- `CHx_FIN_SEL = b10` (single-ended sensor, divide by 2), `CHx_FREF_DIVIDER = 1` → `CLOCK_DIVIDERS_CHx = 0x2001`
- External 40 MHz clock: `CONFIG.REF_CLK_SRC = 1`
- Tune `DRIVE_CURRENT_CHx` so tank amplitude is 1.2–1.8 Vpk (start around IDRIVE = 15)
- Autoscan all 4 channels (`MUX_CONFIG.AUTOSCAN_EN = 1`, `RR_SEQUENCE = b10`), deglitch 10 MHz
